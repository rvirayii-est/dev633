## 2. Plain-English explanation
From lesson 1 to lesson 32 the shop was a program **you ran on your own computer**. A real shop has a cashier's screen, a phone app for the owner and maybe a supplier's system, all using the **same** stock and sales. That needs one program that keeps the data and **other programs that ask it questions over a network**. The web is exactly that.

### Client and server
- A **server** is a program that waits for questions and answers them.
- A **client** is a program that asks: a browser, a phone app, `curl`, or your own Java code.
- The question is a **request**. The answer is a **response**. They travel as plain text using the rules of **HTTP** (HyperText Transfer Protocol). A *protocol* is just an agreed way of talking, like "say hello first, then your name".

HTTP is **stateless**: the server forgets you after every answer. Each request must carry everything the server needs. (That is why the shop API will take the product name in every request.)

### A URL
`http://localhost:8080/products/Rice%2025kg?status=LOW`

| Part | Example | Meaning |
|---|---|---|
| scheme | `http` | the language to speak (`https` = the same, encrypted) |
| host | `localhost` | which computer; `localhost` means *this* computer |
| port | `8080` | which program on that computer (like an apartment number) |
| path | `/products/Rice%2025kg` | which thing you want |
| query | `?status=LOW` | extra options, as `name=value` pairs joined with `&` |

A URL cannot contain spaces. They are written `%20` (or `+` in a query). That is **URL encoding**: `Rice 25kg` becomes `Rice%2025kg`. The server must decode it again.

### A request
```text
GET /products/Rice%2025kg HTTP/1.1
Host: localhost:8080
Accept: text/plain

```
1. **Request line:** the **method** (what to do), the **target** (path + query) and the HTTP version.
2. **Headers:** `Name: value` lines with extra information (who you are, what you accept, how long the body is).
3. An **empty line** ends the headers.
4. An optional **body**: the data you send (for `POST`, for example).

Every line ends with two characters, `\r\n` (carriage return + line feed). You will see them in `RawHttp.java`.

### Methods: the verb
| Method | Means | Changes data? | Example in the shop |
|---|---|---|---|
| `GET` | give me this | no ("safe") | list products |
| `POST` | add / do this | yes | record a sale |
| `PUT` | replace this | yes | change a product's price |
| `DELETE` | remove this | yes | remove a product |

### A response
```text
HTTP/1.1 404 Not Found
Content-type: text/plain; charset=utf-8
Content-length: 21

Unknown product: salt
```
The first line has the **status code** and its words. The **headers** describe the body (`Content-type` says what kind of data it is). Then the empty line and the **body**.

### Status codes: the answer in one number
The first digit tells the story:

| Range | Meaning | Codes you will use |
|---|---|---|
| 2xx | it worked | `200 OK`, `201 Created` (something new was made), `204 No Content` |
| 4xx | **the caller** made a mistake | `400 Bad Request` (bad input), `404 Not Found`, `405 Method Not Allowed`, `409 Conflict` (the request is fine but clashes with the current state, such as not enough stock) |
| 5xx | **the server** has a bug or broke | `500 Internal Server Error` |

Rule of thumb: 4xx means "fix your request", 5xx means "not your fault, we will fix it".

### The shop as a web server
`ShopHttpServer` (in `src/main/java/dev/javabybuilding/web`) puts the lesson 32 shop behind HTTP. It uses only the JDK:
`com.sun.net.httpserver.HttpServer` receives requests, `java.net.http.HttpClient` sends them. It answers in plain text.

| Request | Answer |
|---|---|
| `GET /health` | `200`, `OK` |
| `GET /products` | `200`, one line per product: `name,price,quantity,status` |
| `GET /products?status=LOW` | the same, only products with that status |
| `GET /products/Rice%2025kg` | `200` and the line, or `404` if there is no such product |
| `POST /sales` with a form body `product=Rice+25kg&quantity=2` | `201` and the receipt line; `404` unknown product, `409` not enough stock, `400` bad input |
| anything else | `404`; a known path with the wrong method gives `405` and an `Allow` header |

The shop code did **not** change: the server calls `Shop.products()`, `Shop.getProduct(...)` and `Shop.sell(...)` and turns the shop's exceptions (`UnknownProductException`, `InsufficientStockException`, `InvalidInputException`) into `404`, `409` and `400`. That mapping is the first taste of lesson 34's design and lesson 39's error handling.

### The pain (on purpose)
Look at what you wrote by hand:
- **routing:** `if (first.equals("products") && count == 2)` for every path;
- **decoding** paths and query strings (`Http.segments`, `Http.query`);
- **status codes** and the `Allow` header;
- **reading** and **writing** bytes, and setting `Content-type` yourself;
- **text only:** a program that wants to read the products must parse comma lines. In lesson 35 you fix that with JSON.

None of it is hard, but a real API has fifty routes. From lesson 36 Spring Boot does all of it; you will keep only the interesting part, the shop's rules.

## 7. Common mistakes and troubleshooting
| Symptom | Cause | Fix |
|---|---|---|
| `java.net.BindException: Address already in use` | Another program (or an older copy of this server) already uses port 8080 | Stop it with `Ctrl+C`, or start on another port: `... ShopHttpServer 9090` |
| `curl: (7) Failed to connect ... Connection refused` | The server is not running, or you are using a different port | Start it in the other terminal and keep that terminal open |
| `404 Not found: /products/Rice` | The name has a space and you left it out or split it | Encode the space: `Rice%2025kg` (or quote the URL in the terminal) |
| In PowerShell `curl` prints a long object or asks questions | `curl` is an alias of `Invoke-WebRequest` in Windows PowerShell | Type `curl.exe`; or use `Invoke-RestMethod` (see docs/SETUP.md) |
| Only the first part of the URL is sent (`?status=LOW&x=1`) | The terminal treats `&` as "run in the background" | Put the whole URL in double quotes |
| `405 Method Not Allowed` for a path that exists | The path exists but not for that method | Read the `Allow` header: it lists the method that works |
| `POST /sales` returns `400 Missing field: product` | The body was not sent as a form: `-d` sends `application/x-www-form-urlencoded` data; check the quotes | Use `-d "product=Rice+25kg&quantity=2"` |
| The test hangs for a long time | A test started a server and failed before `close()` | Use `@AfterEach` to close it, as `ShopHttpServerTest` does |
| `500 Something went wrong on the server.` | An unexpected exception (a bug) | Read the stack trace in the server window; 5xx is never the caller's fault |
