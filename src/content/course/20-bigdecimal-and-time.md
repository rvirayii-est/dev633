## 2. Plain-English explanation
- **Why not `double`?** A `double` stores numbers in binary. `0.1` has no exact binary form, just like 1/3 has no exact decimal form (0.3333...). So `0.1 + 0.2` is slightly off. For a science program that is fine. For a till it is not: tiny errors add up, and a customer's total must be exactly what the receipt says.
- **Why we used `int` centavos until now.** Storing 1250.50 pesos as the whole number `125050` is exact and fast. It served us for 19 lessons. But it has costs: every method had to remember "this `int` is centavos", printing needed `/ 100` and `% 100`, percentages needed `long` to avoid overflow, and an `int` overflows near PHP 21 million (the code even carried a `shortcut:` comment promising to fix this "in week 5"). Real systems use a decimal type. This is that lesson.
- **`BigDecimal`.** An exact decimal number with as many digits as you like. It is an **object**, so there are no `+ - * /` signs: `a.add(b)`, `a.subtract(b)`, `a.multiply(b)`, `a.divide(b, 2, RoundingMode.HALF_UP)`. It **never changes**: `a.add(b)` returns a new number and `a` stays the same. Its **scale** is the number of decimals: `2.50` has scale 2.
  1. **Build it from text.** `new BigDecimal("0.10")` is exact. `new BigDecimal(0.10)` copies the double's error (0.1000000000000000055...). `BigDecimal.valueOf(0.1)` is also safe.
  2. **Compare with `compareTo`.** `equals` says `2.0` and `2.00` are different (different scale). `a.compareTo(b)` is `0` when they are worth the same, negative if `a` is smaller, positive if bigger. Our code avoids the trap by **always keeping scale 2** (`Money.round`), which is why `assertEquals(Money.of("1250.50"), product.getPrice())` works in tests.
  3. **Say how to round.** `1 / 3` never ends, so `divide` without a rounding rule throws `ArithmeticException`. `divide(three, 2, RoundingMode.HALF_UP)` means "2 decimals, round .5 up". Money rounding in the shop: VAT rounds **half up**; a percentage discount rounds **down** (exactly what `int` division always did, so the amounts did not change).
- **The refactor, step by step.** Changing a type that runs through the whole program is the largest kind of refactor. The compiler is your guide: change the type in one place, and it lists every place that now breaks.
  | Step | What changed |
  |---|---|

  | 2 | `PriceCalculator`, `Product`, `SaleLine`, `Sale`, `StockReport`: `int` fields and methods became `BigDecimal` (`getPriceCentavos()` became `getPrice()`) |
  | 3 | `Discount` and its four classes: `discountFor(BigDecimal)`; `Discounts.best` uses `compareTo` |
  | 4 | `Customer.pointsFor` uses `divideToIntegralValue` (how many whole PHP 100) |
  | 5 | `Validation.parseCentavos` (returned `-1`) became `parseMoney` (returns `null` for "not an amount": `-1` is a legal `BigDecimal`); `InputReader.readMoney` follows |

- **Dates and times: `java.time`.** Never `Date` or `Calendar` (old and confusing). The types you need:
  | Type | Holds | Example |
  |---|---|---|
  | `LocalDate` | a day, no time | `LocalDate.of(2026, 3, 1)` |
  | `LocalTime` | a time of day | `LocalTime.of(9, 30)` |
  | `LocalDateTime` | both, no time zone | `2026-03-01T09:30` |
  | `Instant` | one exact moment on the world timeline | `2026-03-01T01:30:00Z` |
  | `ZoneId` / `ZonedDateTime` | a place's rules (`Asia/Manila` is UTC+8, no daylight saving) | |
  | `Duration` / `Period` | an amount of time: hours and minutes / years, months, days | `Duration.ofMinutes(95)` |
  They are all **immutable** like `BigDecimal`: `day.plusDays(2)` returns a new date. `DateTimeFormatter.ofPattern("dd MMM yyyy, h:mm a", Locale.US)` turns one into text; `LocalDate.parse("2026-03-01")` turns text into one.
- **Which one in the shop?** The shop is in one place, so a sale is stamped as a `LocalDateTime` on the shop's wall clock (`Asia/Manila`). A system that serves several countries should store `Instant`s and convert for display.
- **A `Clock` instead of `now()`.** `LocalDateTime.now()` reads the computer's clock: a test using it gives a different answer every second, and cannot test "sales on 1 March". Instead `Inventory` has a `Clock` field. In the real app: `Clock.system(zone)`. In tests: `Clock.fixed(...)` (always the same moment) or the small `TestClock` in the test folder (a clock you move forward with `advance`). Passing in what a class depends on is called **dependency injection**, and it is the same idea as passing a `Scanner` and `PrintStream` in lesson 06.
- **Files outlive code.** Lesson 19 saved `priceCentavos` and no times. Anyone who ran lesson 19 has files in that format. If lesson 20 refused them, their data would be stuck. `DataStore` recognises the old *header* and upgrades each row on the way in: `125050` centavos become `1250.50`; a coupon `fixed:5000` becomes `fixed:50.00`. The old files recorded no times and **we do not invent any**: upgraded rows get the obvious placeholder `1970-01-01T00:00` (`DataStore.UNKNOWN_TIME`). The next save writes the new format.
- **New in the app:** `Money`; timestamps on `Sale` (`getDateTime`, `receiptHeader`) and `StockMovement` (`at`); `Inventory(Clock)`, `salesOn(LocalDate)`, `salesTotalOn(LocalDate)`; a three-line-longer `DataStore`. **Milestone M4 is reached:** `Main` loads `shop-data/` when the app starts and saves it when you choose Quit.

## 7. Common mistakes and troubleshooting
| Symptom | Cause | Fix |
|---|---|---|
| `Non-terminating decimal expansion; no exact representable decimal result.` | `divide` without a rounding rule on a number like 1/3 | `divide(x, 2, RoundingMode.HALF_UP)` |
| `assertEquals` fails: expected `2.0` but was `2.00` | `BigDecimal.equals` compares scale too | Round to scale 2 (`Money.round`) or compare with `compareTo` |
| A price like `0.1000000000000000055...` | `new BigDecimal(0.1)` was built from a double | `new BigDecimal("0.1")` or `BigDecimal.valueOf(0.1)` |
| `Rounding necessary` (ArithmeticException) from `Money.of("1.005")` | The text has more than 2 decimals and `of` refuses to drop digits silently | Decide how to round (`Money.round`), or reject the input as `Validation.parseMoney` does |
| `bad operand types for binary operator '+'` | Using `+` on `BigDecimal` | `a.add(b)` |
| The result of `a.add(b)` seems lost | `BigDecimal` never changes; you threw the new value away | `total = total.add(b);` |
| Test fails only after midnight or on another computer | The code called `LocalDateTime.now()` | Take a `Clock` and call `LocalDateTime.now(clock)` |
| `DateTimeParseException: Text '1 March 2026' could not be parsed` | The text is not in ISO format (`2026-03-01`) | Parse with a `DateTimeFormatter` pattern, or write ISO dates |
| `products.csv, line 2: not an amount of pesos: ...` | An old file was edited, or an amount has 3 decimals | Fix the cell to at most 2 decimals |
| The old `shop-data` shows sales dated `1970-01-01` | Lesson 19 files had no times | Expected: it is the "unknown" placeholder |
