## 1. Learning objectives
After this lesson you can:

- use `filter` (keep some), `map` (change each), `sorted`, `limit`, `distinct`, `mapToInt(...).sum()`;
- end a pipeline with `toList()`, with `collect(Collectors...)` (`groupingBy`, `counting`, `joining`) or with an `Optional`;
- turn a `for` loop into a stream and back, and decide which one is easier to read;
- write the shop's reports: what needs restocking, revenue per payment method, the biggest sale.

## 2. Plain-English explanation
- **A stream is a conveyor belt.** `products.stream()` puts the products on a belt. Each step (`filter`, `map`, ...) does one small job as they pass. The last step, the **terminal operation**, collects the result. The original list is never changed.
  ```java
  products.stream()                       // 1. source
          .filter(p -> !p.status().equals("OK"))   // 2. keep only LOW and OUT
          .map(Product::getName)                   // 3. turn each product into its name
          .toList();                               // 4. the ending
  ```
- **Nothing runs until the ending.** Steps 2 and 3 only describe the work; `toList()` makes it happen.
- **Lambda and method reference.** `p -> p.getQuantity() > 0` is a tiny nameless method ("a lambda"): for each `p`, answer yes or no. `Product::getName` is a shorter way to write `p -> p.getName()`.
- **Numbers.** `mapToInt(Product::stockValue)` makes a stream of plain `int`s that has `sum()`, `average()`, `max()`.
- **Optional.** `max(...)` on an empty stream has no answer. Java does not return `null`; it returns an **Optional**, a box that is either full or empty. You open it with `orElse("none")`, `orElseThrow()`, `isEmpty()`, or `map(...)`. A cashier asking "what was the biggest sale today?" on a day with no sales gets an honest "nothing", not a crash.
- **Collectors.** `Collectors.groupingBy(Sale::getPayment, ...)` makes a `Map` with one entry per payment method. `summingInt(Sale::total)` adds each group up; `counting()` counts it; `joining(", ")` glues text together.
- **Loop or stream?** Streams shine for "filter, change, collect" questions. A loop is clearer when the body does several different things, changes more than one variable, or needs to stop halfway. Neither is "better"; clear wins.

## 7. Common mistakes and troubleshooting
| Symptom | Cause | Fix |
|---|---|---|
| `stream has already been operated upon or closed` | A stream was used twice | Call `list.stream()` again; a stream is single-use |
| Nothing happens | The pipeline has no terminal operation | End with `toList()`, `sum()`, `collect(...)`, `forEach(...)`... |
| `incompatible types: Stream<String> cannot be converted to List<String>` | Missing the ending | Add `.toList()` |
| `NoSuchElementException: No value present` | `orElseThrow()` / `get()` on an empty Optional | Use `orElse(...)`, `isEmpty()` or `map(...)` |
| `local variables referenced from a lambda expression must be final` | A lambda tried to change an outer variable | Do not mutate from a lambda: use `sum()`/`collect`, or `Counter.add` on an object |
| `ConcurrentModificationException` while streaming | The source list is changed inside the pipeline | Build a new result instead of changing the source |
| Wrong order in a `HashMap` result | `groupingBy` returns a `HashMap` | Pass `TreeMap::new` as the second argument for sorted keys |
| `int` average prints `3` instead of `3.5` | Integer division | `average()` gives a `double`; do not divide ints yourself |
