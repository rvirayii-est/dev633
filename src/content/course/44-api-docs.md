## 1. Learning objectives

- **improve** it: a title, one-line summaries, tags, the way to sign in, and the shared error shape;
- **try** an endpoint in the browser with *Swagger UI*, including the password;
- **test** the documentation against lesson 34's design table, so the docs cannot silently go out of date.

## 2. Plain-English explanation
Another developer (or you, in six months) asks: "What can this API do? What do I send? What comes back? What if I am not allowed?" The answer should not be "read the controllers" or "ask Ana". It should be a **document**, always current, that a person can read and a program can use.

**OpenAPI** (formerly called Swagger) is the standard format for that document: a JSON (or YAML) file listing every path, method, parameter, request body, response and error. Because it is a standard, tools can use it: show it as a web page, generate a client in another language, build test requests, or check that a server obeys it.

**springdoc-openapi** is a library that *reads your Spring controllers* and writes that document for you, so the description comes from the code and cannot lie much. You add one dependency and get:

| URL | What |
|---|---|
| `/v3/api-docs` | the OpenAPI document, as JSON |
| `/swagger-ui.html` | a web page built from it, where you can try each endpoint |

### Which version?
springdoc is not part of Spring Boot, so its version must fit the Spring Boot in the root `pom.xml` (3.5.x). The **2.8.x** line of springdoc is the one made for Spring Boot 3.5 (springdoc 3.x is for Spring Boot 4). The root `pom.xml` fixes `springdoc.version` at **2.8.17**, which exists on Maven Central and which this lesson's tests and server ran against. Like every version in the course it lives only in the root `pom.xml`; the lesson `pom.xml` just names the library.

### What springdoc finds by itself, and what you add
By reading `ProductController` it already knows the paths, the methods, the path variables and query parameters, the request bodies (and their validation rules from lesson 39: `@NotBlank`, `@Min`...) and the response shapes. It cannot know the *meaning* in your head, so you add it with annotations and a small config class:

| You add | With | Why |
|---|---|---|
| a short sentence per endpoint | `@Operation(summary = "...")` | The list in Swagger UI is read by people |
| a group name and description | `@Tag(name = "Products", description = "...")` on the controller | Groups the endpoints |
| title, version, description, contact | the `OpenAPI` bean in `OpenApiConfig` | The front page of the document |
| how to sign in | a `SecurityScheme` of type HTTP Basic, plus a security requirement | The **Authorize** button; marks each endpoint as "needs a login" |
| the error shape | an `OpenApiCustomizer` that adds the `ErrorResponse` schema and the `401` and `403` answers to every secured operation | A client then knows what an error looks like |

Annotations go **on the code they describe**, so they are changed together with the code. A description in a separate Word file is out of date the week it is written.

### Documentation is also an attack map
The document lists every endpoint. That is its job, but it also helps an attacker. The rules we follow:
- the document describes the API, never the data: `OpenApiTest` checks that no product name or password appears in it;
- it is public here (`SecurityConfig` lets `/v3/api-docs/**` and `/swagger-ui/**` through), so a new developer can read it without an account. It could be required to sign in too; that is a choice for the team;
- a real deployment may close the Swagger page: set `springdoc.swagger-ui.enabled=false` (and `springdoc.api-docs.enabled=false` to close the document). Lesson 46 shows how to flip such settings with environment variables.
Authorization is still enforced by the API itself: showing an endpoint in the document does not open it.

### Testing a document
`OpenApiTest` reads the real document and checks that:
- every endpoint of `ApiDesign.ENDPOINTS` (lesson 34's table) is in it, with the right method;
- every operation has a summary (nobody forgot to describe a new endpoint);
- the sign-in method is described, and only `/hello` is public;
- the error shape is there, and secured operations list `401` and `403`;
- no shop data leaked into it.
Add an endpoint without documenting it and the build fails: the same trick as the design-table test of lesson 40.

## 7. Common mistakes and troubleshooting
| Symptom | Cause | Fix |
|---|---|---|
| `/v3/api-docs` answers `401` | The documentation paths are not open in `SecurityConfig`, or the rule is below the catch-all | Add the `permitAll()` rule above `.anyRequest()` |
| `/v3/api-docs` answers `500` or `NoSuchMethodError` at start-up | springdoc and Spring Boot versions do not fit | springdoc 2.8.x for Spring Boot 3.5; check the root `pom.xml` |
| Swagger UI shows "Failed to load API definition" | The page cannot read `/v3/api-docs` (blocked, or an error inside the generator) | Open `/v3/api-docs` in the browser and read the error |
| Swagger UI says `401 Unauthorized` on every call | Not authorised in the page | Click **Authorize** and enter a username and password |
| An endpoint is missing from the document | It is in a package the scan does not reach, or it is hidden with `@Hidden` | Keep controllers below `dev.javabybuilding` |
| The document shows `"*/*"` for responses | The mapping has no `produces` | `produces = MediaType.APPLICATION_JSON_VALUE` (exercise stretch) |
| The 401 and 403 answers are missing from some operations | The customizer skips `/hello`, and runs only when the document is built | Check `OpenApiConfig`; `OpenApiTest` names the path |
| `Servers: http://localhost:8080` is wrong in a deployed app | springdoc builds it from the request | Behind a proxy set `server.forward-headers-strategy=framework`, or define `servers` in the `OpenAPI` bean |
| The generator breaks when you add a new return type | A type it cannot describe (for example a raw `Object`) | Return a record, as the course does everywhere |
| You documented the data (names, prices) in an example | Examples are public with the document | Use made-up examples only |
