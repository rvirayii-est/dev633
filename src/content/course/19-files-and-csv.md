## 2. Plain-English explanation
- **Memory forgets.** Everything the app holds (lists, maps, objects) disappears when it stops. A **file** keeps text on disk. This lesson saves the shop at the end of a run and loads it at the start of the next.
- **`Path` and `Files`.** A `Path` is the address of a file or folder: `Path.of("shop-data")`, then `dir.resolve("products.csv")`. The `Files` class does the work: `Files.readAllLines(path)` gives a `List<String>`, `Files.write(path, lines)` writes one. Text is read and written as UTF-8, so Filipino names and symbols are safe.
- **CSV.** One record per line, fields separated by commas, the first line a header naming the columns:
  ```
  name,priceCentavos,reorderLevel,quantity
  Rice 25kg,125050,10,12
  ```
  Excel and Google Sheets open it directly. **The catch:** a product called `Rice, premium 5kg` contains a comma. So a field with a comma, a quote or a line break is wrapped in double quotes, and a quote inside it is written twice: `"Rice, premium ""5kg"""`. `line.split(",")` cannot do that, so the course has a small `Csv` class (`escape`, `join`, `parseLine`). In real projects you would use a library; writing it once teaches what the library does.
- **Checked exceptions.** Opening a file can fail for reasons the program cannot control (no such file, disk full, no permission). Java reports this with `IOException`, a **checked** exception, so the compiler makes every caller either catch it or write `throws IOException`. `NoSuchFileException` is one kind of `IOException`: catch it when "no file yet" is a normal situation.
- **Two kinds of file problem, two exceptions.** If the file cannot be opened, you get `IOException`. If it opens but its *contents* are wrong (a word where a number belongs), the app throws our own `DataFileException` with the file and line number: `products.csv, line 3: not a whole number: seventy five`. Someone who edited the file by hand can fix it.
- **Do not trust files.** A file can be edited, cut off, or from an older version. `DataStore.load` checks the header, the column count, every number, and that the shelf quantities in `products.csv` agree with the log in `movements.csv`. It refuses a shop whose files disagree.
- **Safe saving.** `writeLines` writes to `products.csv.tmp` first and then *moves* it over the real file. If the power fails while writing, the old file is still whole.
- **try-with-resources.** Anything that must be closed (a writer, a reader) goes in `try ( ... )`. Java closes it at the end of the block, even after an exception. `Files.readAllLines` and `Files.write` open and close for you, which is why the app uses them.
- **Turning objects into text.** A `Discount` is an object; a file holds text. `DiscountCodes` translates: `percent:10`, `fixed:5000`, `senior`, `none`. A sale with several lines becomes several rows with the same sale number; loading groups them back with a `Map`. Loyalty points are not stored: they are **worked out again** from the sales (one source of truth).
- **Testing file code.** A test must not write into your project. JUnit's `@TempDir Path dir` gives each test a fresh empty folder and deletes it afterwards. Every test in this lesson uses it, so `git status` stays clean.
- **New in the app:** `Csv`, `DiscountCodes`, `DataStore` (`save`, `load`, `exists`), `DataFileException`, a `Product` constructor that restores a quantity, `Inventory.restore(...)`, and `Main` which loads the `shop-data` folder at start and saves it on Quit. `shop-data/` is in `.gitignore`: data is not source code.
- **What stays as it is.** Money is still whole centavos in the files (`priceCentavos`). Lesson 20 changes the money type, and the file format with it, and shows how an old file is still read.

## 7. Common mistakes and troubleshooting
| Symptom | Cause | Fix |
|---|---|---|
| `unreported exception IOException; must be caught or declared to be thrown` | A file method can fail and the compiler insists you decide what happens | Add `throws IOException` (let the caller decide) or catch it where you can do something useful |
| `NoSuchFileException: shop-data\products.csv` | You loaded a folder that holds no save | Check `DataStore.exists(dir)` first (as `Main.loadOrSample` does) |
| Fields shift one column to the right | A comma inside a name, and the line was split with `split(",")` | Use `Csv.parseLine` and `Csv.join`, which handle quotes |
| `products.csv, line 3: not a whole number: ...` | A hand-edited cell, or a spreadsheet saved `1250.50` | Fix the cell. Lesson 20 changes the price format to decimals |
| Accents or `₱` look broken | The file was saved by an editor in another encoding | Save as UTF-8, which `Files` expects |
| A test passes alone but fails after another | Both tests used the same real file | Give each test its own `@TempDir` |
| New `shop-data/` or `.csv` files show up in `git status` | A test or demo wrote into the project folder | Tests: use `@TempDir`. Running the app: `shop-data/` is already in `.gitignore` |
| The data looks right but the old file is half written | The program stopped during the write | `DataStore` writes `.tmp` first and moves it; a leftover `.tmp` file can simply be deleted |
